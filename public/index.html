MCP server

Ask for a film in plain language.
Your Seerr does the rest.

SeerrSense sits in front of Overseerr or Jellyseerr and speaks the Model Context Protocol, so Claude, ChatGPT or any MCP client can search your catalogue, work out which title you actually meant, and file the request on your own server.

What it adds to the Seerr stack

Seerr already knows your library and talks to Radarr and Sonarr. What it does not do is take a vague sentence and turn it into the right TMDB id.

Resolution, not just search

“That submarine film with the German crew” goes through Seerr’s own search first, then a normalised retry, and only then a language model that proposes titles, people and years — never an id. Every candidate is verified against Seerr before it is offered.

Your server, your rules

Requests are filed through your Seerr instance with your API key, so quotas, approvals and the existing request history keep working exactly as before.

Writes are guarded

Before anything is requested, SeerrSense re-reads the canonical record and refuses when the title is already available or pending. The write tool needs its own scope.

How a request travels

SeerrSense holds no library of its own. It resolves, then hands the work to the stack you already run.

MCP tools

Four tools, one of which writes. The same operations are also available over REST at /api/v1.

ToolWhat it doesScope
search_media Exact or fuzzy search straight through Seerr, films and series only. seerr:read
resolve_media Turns a description into verified candidates: native search, normalised retry, then language-model intent checked back against Seerr. seerr:read
get_media The canonical record for one TMDB id, including availability. seerr:read
request_media Files the request, optionally for named seasons. Refuses when the title is already available, pending or blocklisted. seerr:request

Connecting to Seerr

One instance, one API key, read through the same endpoints the web interface uses.

Credentials

SEERR_URL and SEERR_API_KEY. Nothing is written anywhere else, and no catalogue data is stored by SeerrSense.

Behind Cloudflare Zero Trust

Set CF_ACCESS_CLIENT_ID and CF_ACCESS_CLIENT_SECRET and the service-token headers travel with every call to Seerr.

Optional semantic layer

With NEBIUS_API_KEY set, unresolved phrasings go through a language model that proposes titles for verification. Without it, search still works.

Set it up

Use the hosted endpoint, or run it yourself next to your Seerr.

  1. Add the MCP server. Point your client at the endpoint above and give it the bearer token you were issued. 
    {
  "seerrsense": {
    "serverUrl": "https://seerrsense.mctl.ai/mcp",
    "headers": { "Authorization": "Bearer <your token>" }
  }
}
  2. Or run it locally. Standalone binaries for Linux, macOS and Windows are attached to every release, and the server speaks stdio for clients that prefer to own the process. 
    seerrsense stdio
  3. Ask for something. “Find that heist film Michael Mann made in the nineties and request it.”

Questions

Does it replace Overseerr or Jellyseerr?

No. It is a layer in front of one. Every request is filed through your Seerr, which keeps owning quotas, approvals, notifications and the request history.

Can an assistant request things on its own?

Requesting is a separate scope from reading, and the tool description tells the model to confirm with you first. The server also re-reads the canonical record and refuses to file a request for something already available or pending.

How is access controlled?

The MCP endpoint requires a bearer token. The server can also act as its own OAuth 2.1 authorization server with Google as the identity provider, in which case each person signs in with their own account, tokens are short-lived and can be revoked individually, and access is limited to an explicit list of addresses.

Does a language model see my library?

Only the phrase you typed is sent, and only when the ordinary search paths fail. The model proposes titles, people and years; it never returns provider ids, and every candidate is verified against Seerr before you see it.

Can I self-host it?

Yes. It is a single container, or a standalone binary, with three required settings. See the repository for the full list.
